# Brief-first meeting preparation and clean export

## Scope and status
This implements the accepted brief-first direction under the [standing development policy](docs/strategy/standing-development-policy.md). It is a local C3 application milestone, not customer acceptance, deployment, new research, product generation, sharing or approval. The original retained account package and current private preview are unchanged.

## Delivered behavior
- An account-qualified `?brief=1` reading surface puts purpose, up to three relevant facts, labeled interpretation/hypothesis, opening, three questions, close and one visible uncertainty note before collapsed evidence/history detail. Existing drafts remain accessible in the full review surface.
- `src/c3/brief-first.ts` constructs one reading/export representation. Existing generated/replayed content is projected without altering its original records. Selected passages and canonical sources are counted separately; unknown dates, distinct context conflicts, source URLs and source excerpts remain inspectable. Sparse evidence is not filled with invented facts.
- A generic authored-copy form accepts explicit title, audience/duration, purpose, facts, interpretation, opening, questions/probes, close, uncertainty and retained evidence IDs. There is no customer-specific renderer or seeded product-model output. The accepted reference is QA input, not a fabricated historical generation.
- `Keep authored copy` updates only session work. Explicit Save persists the optional `authoredCopy` beside immutable raw generation records through the existing work store/version/CAS mechanism. It never changes record origin, evidence identity or approval. Clear is a session mutation until saved. Old files without this optional field continue to load unchanged.
- Authored text is labeled **User-authored meeting copy**. A generated revision leaves the prior authored copy labeled stale until explicitly reviewed/kept against the new record. Selected IDs must exist in the frozen work context; stored authored bindings must name a retained record.
- Copy and actual `.md`/`.txt` downloads use the same server-formatted text, not DOM scraping. POST export validates current account/document/context/record/work version. Unsubmitted editor changes, stale tabs and active operations refuse export. Clipboard denial gives truthful status and selectable fallback text. Copy/download do not save.

## Limits
Authored text is user input, not semantically validated evidence or content approval. Existing generated briefs may remain verbose; they are not silently rewritten to match the authored reference. Plain-text and Markdown downloads intentionally contain identical canonical Markdown-formatted text. Local session retention is not durable until explicit Save. No product-generated revision was requested in browser QA; revision contracts are covered by offline regressions. No deployment/private-preview upgrade is included. Customer acceptance remains Andrew's judgment.
