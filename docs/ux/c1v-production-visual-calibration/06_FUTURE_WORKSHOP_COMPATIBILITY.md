# Future Workshop compatibility

Status: **static design compatibility evidence only — not an active C1 surface and not C3 implementation**

The owner asked each visual direction to demonstrate that a future calm account-local mode could support:

`Account | Workshop`

and the accepted two-input `04-prepare-composer-future-c3.png` direction without turning Atliera into a Salesforce-style navigation system.

## Direction A

`direction-a/future-workshop-compatibility.html` extends the editorial folio:

- a narrow plum mode rail provides the future Account/Workshop relationship;
- the main canvas preserves authored typography and purposeful whitespace;
- audience and objective appear as static editorial fields;
- evidence context remains a quiet side note rather than application chrome.

The frame contains no links, buttons, inputs, route, form, or generation behavior.

## Direction B

`direction-b/future-workshop-compatibility.html` extends the evidence horizon:

- a slim dark mode bar holds the future Account/Workshop relationship;
- the composer sits on mineral paper rather than inside the active evidence field;
- audience and objective are static semantic blocks;
- inherited context is visibly bounded from the future composing space.

The frame contains no links, buttons, inputs, route, form, or generation behavior.

## Compatibility conclusion

Both directions can host a future account-local Workshop without importing dense side navigation, object trees, global search, account switchers, notification chrome, fake controls, or current C3 behavior.

This frame does not select a direction, authorize Workshop, implement Prepare, create a meeting brief, or begin C3. Any future implementation requires separate exact authorization and new trust, responsive, and user gates.
